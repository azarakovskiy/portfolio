Platform migration

A staged path out of the monolith

Routing and authentication moved into shared services while product teams gained control of their own routes and authorization rules.

gateway throughput
10k+ RPS
parallel operation
6 to 12 months
authorization adopted
7 teams
The problem

Routing and authentication still lived in a PHP monolith, so service teams had to change shared endpoints whenever their own APIs changed.

My ownership

I helped form the gateway team with one colleague; we later grew to four engineers. I contributed to the Go gateway, authentication service, authorization library, and staged migration. We shared authorship of the work.

Technical decisions

We built the gateway on Zalando Skipper and used DynamoDB for the high-throughput authentication service. Custom Kubernetes CRDs and Helm-based registration let service teams publish routes without manual gateway changes, while a Go authorization library let them define and test their own rules. I added a Redis idempotency guard for one-time JWT signup tokens and containerized integration tests.

Result

We ran the old and new systems side by side for about six to twelve months, then removed routing and authentication code from the PHP monolith. The gateway handled more than 10,000 requests per second, and all seven cross-functional teams adopted the authorization library. I contributed the CRD routing work upstream to Zalando Skipper.
